# 관리자인증 - 403에러 - JWT콜백미조회

## 📋 문제 요약
- **발생 위치**: 관리자 페이지 (`/admin/*`)
- **에러 타입**: 403 Forbidden
- **근본 원인**: JWT 콜백에서 user.role 미조회

## 🔍 상세 상황

### 어떤 문제가 발생했는가?
Google OAuth로 로그인한 사용자가 관리자 페이지 접근 시 403 Forbidden 에러 발생. 세션은 정상적으로 생성되지만 권한 검증 실패.

### 에러 메시지
```
GET /admin/examiners 403 Forbidden
Error: Insufficient permissions
Session: { user: { email: 'admin@example.com', role: undefined } }
```

### 어떤 환경에서 발생했는가?
- **브라우저**: Chrome 119
- **OS**: Windows 11
- **로그인 방법**: Google OAuth
- **관련 파일**:
  - `lib/auth/authOptions.ts:45-67` - JWT 콜백
  - `app/admin/layout.tsx:15-25` - 권한 검증

## 💡 원인 분석

### 왜 이 문제가 발생했는가?
JWT 콜백에서 `user.role`을 그대로 사용하고 있었음. Google OAuth 로그인 시 provider가 반환하는 user 객체에는 role 정보가 없음. 따라서 `session.user.role = undefined`가 되어 권한 검증 실패.

### 어떤 영향이 있었는가?
- Google로 로그인한 모든 관리자가 admin 페이지 접근 불가
- Credentials (ID/PW) 로그인은 정상 작동 (DB에서 user 조회 시 role 포함)
- 약 3명의 관리자 영향 (전체 관리자의 60%)

## 🛠️ 해결 과정

### 무엇을 시도했는가?
1. **세션 로그 확인** - ✅ 성공
   - `console.log(session)` 추가
   - `role: undefined` 확인

2. **JWT 콜백 수정 시도 1** - ❌ 실패
   - `user.role || 'user'` 추가
   - 여전히 undefined (user 객체에 role 없음)

3. **최종 해결** - ✅ 성공
   - MongoDB에서 직접 role 조회
   - JWT 토큰에 role 포함

### 최종 해결 방법
```typescript
// lib/auth/authOptions.ts
import { connectMongoDB } from '@/lib/db/mongodb';
import User from '@/models/User';

export const authOptions: NextAuthOptions = {
  // ...
  callbacks: {
    async jwt({ token, user, trigger, session }) {
      // ✨ 추가: MongoDB에서 role 조회
      if (user) {
        await connectMongoDB();
        const dbUser = await User.findOne({ email: user.email });

        token.id = user.id;
        token.email = user.email;
        token.name = user.name;
        token.role = dbUser?.role || 'user'; // ✨ DB에서 가져온 role
      }

      // session update 처리
      if (trigger === 'update' && session?.user?.role) {
        token.role = session.user.role;
      }

      return token;
    },

    async session({ session, token }) {
      if (session.user) {
        session.user.id = token.id as string;
        session.user.email = token.email as string;
        session.user.name = token.name as string;
        session.user.role = token.role as string; // ✨ JWT에서 role 가져오기
      }
      return session;
    },
  },
};
```

### 어떤 파일을 변경했는가?
- `lib/auth/authOptions.ts:45-67` - JWT 콜백에 DB role 조회 로직 추가
- import 문 추가: `connectMongoDB`, `User` 모델

## 📚 학습 내용

### OAuth의 함정
> "OAuth provider는 인증만 제공할 뿐, 우리 앱의 권한 정보(role)는 제공하지 않는다."

### Source of Truth 원칙
> "권한은 항상 DB를 source of truth로 사용해야 한다. Provider의 user 객체를 맹신하지 말 것."

### JWT 콜백의 역할
> "JWT 콜백은 단순히 user 객체를 token에 복사하는 곳이 아니라, DB에서 최신 정보를 가져오는 곳이다."

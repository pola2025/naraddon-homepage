# 컨텍스트 절약 최적화 Skill

**목적**: 사용자 요청을 분석하여 컨텍스트 효율적인 작업 방식으로 유도

## 🎯 Skill 활성화 조건

다음 패턴이 감지되면 **자동으로 이 Skill이 활성화**됩니다:

1. **광범위한 요청**
   - "코드 검토해줘", "리팩토링해줘", "전체 확인해줘"

2. **위치 불명확**
   - "로그인 관련 수정", "에러 고쳐줘", "아까 그 파일"

3. **불필요한 서론**
   - "안녕하세요", "죄송한데", "제가 작업하던..."

4. **파일 경로 누락**
   - 파일명만 언급하고 전체 경로 없음
   - 라인 번호 없이 "이 부분", "여기" 등으로 지칭

## 📋 검증 체크리스트

### 필수 요소 확인
- [ ] **파일 경로**: 전체 경로가 명시되었는가? (예: `src/app/api/route.ts`)
- [ ] **라인 범위**: 구체적인 라인 번호가 있는가? (예: `:45-67`)
- [ ] **범위 한정**: "~만", "~에서", "~의" 등 범위 제한어가 있는가?
- [ ] **작업 명확성**: 구체적인 작업이 지정되었는가? (예: "에러 핸들링 수정", "타입 추가")

### 자동 통과 조건
다음 중 하나라도 만족하면 검증 없이 진행:
- ✅ 파일 경로 + 라인 번호 + 작업 명시
- ✅ 에러 메시지 + 파일 위치 제공
- ✅ "~만" 키워드로 범위 명확히 제한

## 🔄 개선 제안 프로세스

### Step 1: 요청 분석
```typescript
interface RequestAnalysis {
  hasFilePath: boolean;      // 파일 경로 여부
  hasLineNumber: boolean;    // 라인 번호 여부
  hasScopeLimit: boolean;    // 범위 제한 여부
  hasUnnecessaryText: boolean; // 불필요한 서론 여부
  isEfficient: boolean;      // 효율적 요청 여부
}
```

### Step 2: 비효율 감지 시 응답 템플릿
```markdown
💡 **더 효율적인 요청 방식 제안**

**현재 요청**: "[사용자의 원래 요청]"

**문제점**:
- [ ] 파일 경로 누락
- [ ] 작업 범위 불명확
- [ ] 라인 번호 미지정

**개선된 요청 예시**:
"[구체적인 파일 경로]:[라인 범위]의 [구체적인 작업]만 수행해줘"

**실제 예시**:
현재: "로그인 코드 검토해줘"
개선: "lib/auth/authOptions.ts:45-67의 JWT 콜백 에러 핸들링만 검토해줘"

**이점**:
- ⚡ 컨텍스트 사용량 70% 절감
- 🚀 응답 속도 2-3배 향상
- 🎯 작업 정확도 90%+ 유지

이 방식으로 요청을 수정하시겠습니까?
또는 그대로 진행하시겠습니까? (개선/진행)
```

### Step 3: 사용자 선택 처리
```typescript
// 사용자 응답에 따라
if (response === "개선" || response.startsWith("수정")) {
  // 사용자가 개선된 요청을 다시 입력할 때까지 대기
  waitForImprovedRequest();
} else {
  // 원래 요청으로 진행 (비효율적이지만 사용자 의도 존중)
  proceedWithOriginalRequest();
}
```

## 🎨 효율적인 요청 패턴 가이드

### Pattern 1: 파일 + 라인 + 작업
```bash
"[파일경로]:[시작라인]-[종료라인]의 [작업]만 수행"

예시:
"app/api/policy-news/route.ts:45-67의 에러 핸들링만 수정"
"lib/mongodb.ts:120-135의 연결 풀 로직만 최적화"
```

### Pattern 2: 파일 + 기능 + 범위
```bash
"[파일경로]에서 [기능]의 [문제]만 수정"

예시:
"lib/auth/authOptions.ts에서 JWT 콜백의 role undefined 오류만 수정"
"src/components/Header.tsx에서 네비게이션 타입 에러만 수정"
```

### Pattern 3: 에러 + 위치
```bash
"[에러타입] at [파일경로]:[라인] - [작업]만"

예시:
"TypeError at src/components/Header.tsx:120 - 타입 수정만"
"ReferenceError at lib/utils.ts:45 - 변수 선언 추가만"
```

### Pattern 4: 범위 제한 작업
```bash
"[도메인/컬렉션/모듈] [작업]만"

예시:
"MongoDB policy-news 컬렉션 인덱스 최적화만"
"Next.js API route 캐싱 설정만"
```
